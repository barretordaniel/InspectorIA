Diseña un prototipo de alta fidelidad para una plataforma web responsiva llamada “InspectorIA”.

InspectorIA es una plataforma colombiana de inspección vial inteligente que permite a los ciudadanos reportar daños en la infraestructura vial de manera rápida utilizando inteligencia artificial, visión artificial y geolocalización.

La propuesta principal es convertir una fotografía de un daño vial en un reporte técnico estructurado. El ciudadano debe poder tomar o cargar una fotografía de un daño, y el sistema debe utilizar inteligencia artificial para:

- Identificar automáticamente el tipo de daño vial.
- Clasificarlo como: hueco, grieta, hundimiento o andén roto.
- Estimar su severidad como leve, moderada o grave.
- Obtener automáticamente la ubicación mediante GPS.
- Permitir agregar un comentario opcional.
- Generar un reporte estandarizado.
- Ubicar el reporte dentro de un mapa.
- Permitir descargar el reporte en PDF.

La aplicación debe sentirse moderna, tecnológica, confiable, institucional y muy fácil de utilizar.

IMPORTANTE:
No debe parecer una aplicación gubernamental antigua ni una aplicación genérica de formularios.
Debe transmitir inteligencia artificial, tecnología, ciudad, infraestructura y seguridad, manteniendo una interfaz limpia y profesional.

La plataforma tendrá dos tipos principales de experiencia:

1. CIUDADANO
Persona que encuentra un daño vial y quiere reportarlo rápidamente.

2. ENTIDAD / CONTRATISTA
Usuario institucional que necesita consultar los daños reportados, revisar su ubicación, severidad y reporte técnico.

=====================================
ESTILO VISUAL
=====================================

Crear una identidad visual moderna para “InspectorIA”.

Utilizar:
- Diseño minimalista y profesional.
- Interfaz limpia con bastante espacio en blanco.
- Tarjetas con bordes ligeramente redondeados.
- Sombras muy sutiles.
- Iconografía moderna y consistente.
- Tipografía sans-serif moderna.
- Diseño accesible y fácil de entender.
- Paleta relacionada con tecnología, ciudad e infraestructura.
- Utilizar un color principal azul oscuro o azul tecnológico.
- Utilizar colores de severidad:
  - Verde = leve.
  - Amarillo/naranja = moderado.
  - Rojo = grave.
- Evitar saturar la interfaz de colores.
- Los colores de severidad deben utilizarse principalmente como indicadores y no dominar toda la interfaz.

La plataforma debe ser responsive y estar diseñada principalmente con enfoque mobile-first, pero incluir también las principales vistas de escritorio.

=====================================
ESTADOS ADICIONALES
=====================================

Diseñar también estados alternativos importantes:

- No se pudo obtener la ubicación.
- La fotografía no tiene suficiente calidad.
- No se pudo identificar claramente el daño.
- Error procesando la fotografía.
- No existen reportes en una zona.
- Permiso de ubicación desactivado.

Los mensajes deben ser amigables y ofrecer siempre una acción para solucionar el problema.

Ejemplo:

“No pudimos identificar claramente el daño.”

“Intenta tomar otra fotografía procurando que el daño completo sea visible.”

[ Tomar otra fotografía ]

=====================================
EXPERIENCIA DE USUARIO
=====================================

El flujo ciudadano debe poder entenderse sin instrucciones externas.

Priorizar que reportar un daño sea extremadamente rápido.

Flujo principal:

Inicio
→ Reportar daño
→ Tomar/subir fotografía
→ Analizar con IA
→ Mostrar clasificación y severidad
→ Confirmar ubicación
→ Revisar información
→ Generar reporte
→ Confirmación
→ Ver/descargar PDF

El mapa y el historial deben poder consultarse independientemente.

Para la experiencia institucional:

Acceso institucional
→ Panel
→ Mapa / listado de reportes
→ Seleccionar reporte
→ Revisar detalle
→ Descargar reporte PDF
